# 테이블 화면 개편 + 캐릭터 뽑기 — 설계 문서

- 작성일: 2026-11-19
- 상태: 사용자 검토 대기
- 기반: `2026-11-19-pirate-card-game-design.md` (1단계 완료 상태)

## 1. 의도와 배경

1단계로 1인 플레이가 끝까지 돌아가지만, 사용자가 직접 플레이해 보고 두 가지를 요청했다.

1. **캐릭터를 직접 뽑고 싶다.** 지금은 게임 시작 시 캐릭터가 무작위로 정해진다.
2. **진짜 카드 게임처럼 보여야 한다.** 지금 화면은 버튼과 글자 위주라 "구리다". 실물 카드처럼 생긴 카드, 테이블 배치, 애니메이션이 필요하다.

친구들과 놀 게임이므로, 처음 보는 친구도 "카드 게임이네" 하고 바로 몰입할 수 있는 화면이 목표다.

> 이 문서는 기존 설계 문서의 비목표 중 "화려한 애니메이션·효과음 제외"를 **애니메이션에 한해** 뒤집는다. 효과음은 여전히 제외.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 게임 시작 시 역할을 먼저 확인하고, 캐릭터 2장 중 1장을 고른다. AI도 같은 단계를 거친다.
- 화면 전체를 "나무 갑판 테이블" 스타일(아래 4장)로 다시 만든다.
- 카드를 뽑고·내고·장착하고·빼앗기고, 맞고·회복하고·쓰러지고, 판정 카드를 뒤집는 순간이 애니메이션으로 보인다.

**비목표**
- 효과음, 배경 음악.
- 카드·캐릭터 그림을 직접 그리거나 외부 그림 쓰기. 그림 자리는 계속 이모지.
- 휴대폰 전용 배치. 데스크톱 우선, 폭 360px에서 깨지지 않을 정도면 충분(기존 제약 유지).
- 온라인 멀티플레이(3단계), 바다 이벤트(2단계).

**실패 조건**
- 애니메이션 때문에 다음 행동을 못 하거나, 화면에 보이는 체력·손패가 실제 상태와 어긋난 채로 남는 것.
- 애니메이션이 너무 길어서 AI 턴을 지켜보는 게 지루한 것(한 사건당 0.6초를 넘지 않게).
- 캐릭터 뽑기 단계에서 남의 후보 캐릭터나 역할이 내 화면에 새는 것.
- 원작의 이름·그림·문구가 들어가는 것(기존 제약 유지).

## 3. 제약 (기존 유지 + 추가)

- 기존 계층 구조 유지: `engine/`은 화면을 모르고, `ui/`는 `PlayerView`만 보고 `Action`만 보낸다. 캐릭터 뽑기도 이 흐름(입력 대기 → 행동)으로 만든다. 그래야 3단계에서 친구들이 각자 고를 수 있다.
- 애니메이션은 `ui/` 안에서만 처리한다. 엔진·방장·AI는 애니메이션을 모른다.
- 새 의존성은 Framer Motion 하나(`framer-motion@11`, React 18 호환).
- 운영체제의 "동작 줄이기" 설정(`prefers-reduced-motion`)이 켜져 있으면 이동 애니메이션을 끄고 즉시 상태만 바꾼다.

## 4. 검토한 방식 (Approaches)

**화면 스타일** — 샘플 3가지를 브라우저로 보여주고 사용자가 고름.
- A. 나무 갑판 테이블 (실물 카드, 양피지, 차분한 애니메이션) — **선택**
- B. 다크 디지털 카드 게임 (금테, 빛 효과, 화려한 연출)
- C. 밝은 보물지도 일러스트 (만화풍, 통통 튀는 애니메이션)

**캐릭터 뽑기 방식**
- 2장 중 1장 고르기 — **선택**. 고르는 재미가 있고 매판 다른 캐릭터를 하게 됨.
- 10명 중 자유 선택 — 같은 캐릭터만 고르게 되고, 온라인에서 겹칠 때 규칙이 필요.
- 3장 중 1장 — 7명이면 21장이 필요해 캐릭터 10명으로 부족.

**애니메이션 구현**
- Framer Motion — **선택**. 카드가 손패에서 테이블로 이동하는 연출(같은 카드의 위치 이동), 등장·퇴장, 부채꼴 정렬을 라이브러리가 계산.
- CSS만으로 직접 — 추가 설치가 없지만, 카드 이동마다 출발·도착 위치 계산을 직접 짜야 해서 복잡.
- 게임 엔진(Phaser) — 화면 전체를 캔버스로 다시 만들어야 해서 기존 React 구조를 버리게 됨. 제외.

## 5. 캐릭터 뽑기 (엔진 변경)

### 5.1 흐름
1. 게임 생성 시 역할을 배정한다(지금과 같음). 캐릭터는 아직 없다.
2. `start()` 시 **뽑기 단계**: 선장부터 시계 방향으로 한 명씩, 남은 캐릭터 풀에서 무작위 2장을 받아 1장을 고른다. 고르지 않은 1장은 풀로 돌아간다.
   - 순서대로 하는 이유(Claude의 결정): 캐릭터가 10명뿐이라 7명이 2장씩 동시에 받으면 14장이 필요해서 모자란다. 순서대로 풀에서 받으면 마지막 사람도 남은 4장 중 2장을 받는다.
3. 모두 고르면 체력을 정하고(캐릭터 체력, 선장 +1) 체력만큼 손패를 나눠준 뒤 선장의 첫 턴을 시작한다.
- 테스트용으로 `GameConfig.characters`를 주면 뽑기 단계 없이 지금처럼 바로 시작한다(기존 테스트 유지).

### 5.2 새 입력 대기와 행동
- `PendingView`에 `{ kind: 'chooseCharacter'; seat; options: CharacterId[] }` 추가.
- `Action`에 `{ type: 'chooseCharacter'; character: CharacterId }` 추가. `options`에 없는 캐릭터는 거부.
- 시간 초과 기본 행동: `options[0]`.
- 이벤트: 고른 순간 `{ type: 'characterChosen'; seat; character }` (공개).

### 5.3 화면 상태 (`PlayerView`)
- 뽑기 전 자리는 `SeatView.character = null`, `hp`·`maxHp` = 0, `handCount` = 0.
- `pending`이 `chooseCharacter`이고 그 자리가 내가 아니면, `options`를 빈 배열로 가려서 보낸다(남의 후보는 비공개).
- 역할 공개 규칙은 그대로(내 역할과 선장만 보임).

### 5.4 AI
- 후보 2장 중 체력이 높은 쪽, 같으면 무작위. (단순해도 됨 — 세부는 구현자 판단)

## 6. 화면 (A: 나무 갑판 테이블)

### 6.1 화면 흐름
```
시작 화면 → 역할 확인 + 캐릭터 뽑기 → 게임 테이블 → 결과 화면
```
- **시작 화면**: 나무 탁자 위 양피지 두루마리. 제목 "반란의 돛", 이름 입력, 인원 4~7 선택(카드 모양 버튼), "출항" 버튼.
- **역할 확인 + 캐릭터 뽑기**: 가운데에 뒤집힌 역할 카드가 뒤집히며 공개된다(역할 이름과 승리 조건 한 줄). 그 아래 캐릭터 카드 2장(얼굴 이모지, 이름, 체력 하트, 능력 문구). 하나를 누르면 확정. 다른 사람이 고르는 동안에는 "다른 선원들이 캐릭터를 고르는 중…"과 자리별 진행(고름/고르는 중)을 보여준다.
- **게임 테이블**: 아래 6.2.
- **결과 화면**: 승리 팀 문구를 크게, 모든 자리의 역할 카드가 차례로 뒤집혀 공개, "다시 하기".

### 6.2 게임 테이블 배치
```
┌───────────────────────────────────────────────────────────┐
│   [상대]     [상대]  👑[선장]   [상대]     [상대]   [상대]   │  ← 위쪽 호(arc)에 최대 6명
│                                                           │
│                ┌────┐  ┌────┐          ┌──────────┐       │
│                │ 덱 │  │버린│          │ 항해 일지 │       │  ← 가운데: 덱, 버린 카드, 판정 자리
│                │ 42 │  │카드│          │ (로그)    │       │     오른쪽: 최근 사건 로그
│                └────┘  └────┘          └──────────┘       │
│  ┌────────────┐                                           │
│  │ 나: 반란 선원 │  [장비] [장비]                   [턴 종료] │  ← 내 정보·장비·턴 종료
│  │ 요리사 톰 ♥♥♥♥│                                          │
│  └────────────┘     ╲ [칼질][피하기][럼주][망원경][결투] ╱      │  ← 부채꼴 손패
└───────────────────────────────────────────────────────────┘
```
- 배경: 나무결 무늬의 갈색 탁자(샘플 A).
- **상대 패널**: 얼굴 이모지, 이름, 체력 하트(♥/♡), 손패 장수(작은 카드 뒷면 아이콘 × n), 장비 카드 축소판, 공개된 역할, 내 기준 거리. 선장은 왕관. 지금 턴인 사람은 금빛 테두리가 은은하게 빛남. AI는 작은 🤖 표시. 쓰러진 사람은 흑백 + 역할 카드 공개.
- **카드 앞면**: 양피지 색 종이, 왼쪽 위 문양·숫자(♥♦는 빨강), 가운데 큰 이모지, 아래 이름. 장비는 푸른빛 종이. 마우스를 올리면 카드 위에 효과 설명 말풍선.
- **카드 뒷면**: 붉은 줄무늬 + 금테 + 해적 깃발(덱, 상대 손패, 뒤집히기 전 카드).
- **손패**: 아래쪽 부채꼴. 마우스를 올린 카드가 위로 올라오고 커짐. 낼 수 있는 카드는 살짝 위로 떠 있고, 낼 수 없는 카드는 약간 어둡게.
- **대상 고르기**: 대상이 필요한 카드를 누르면 카드가 들린 상태가 되고, 고를 수 있는 상대 패널이 금빛으로 깜빡임. 사거리 밖은 흐리게. 소매치기·밧줄 자르기는 대상을 누르면 그 상대의 장비와 "손패 무작위"(손패가 있을 때만) 중에서 고르는 작은 창.
- **응답 창**(공격받음, 결투, 쓰러지기 직전, 버리기, 전리품, 판정 선택, 자리 고르기, 뽑을 곳): 테이블 가운데에 양피지 쪽지 모양 창. 내야 할 카드가 손패에서 강조되고, 카드를 직접 눌러서 내거나 "맞기/포기" 버튼.
- **관전 중**: 내가 쓰러지면 손패 자리에 "관전 중" 띠, 역할 카드 공개.
- 거부 메시지는 화면 아래 양피지 쪽지 토스트로 2초.

### 6.3 애니메이션
방장이 새 `PlayerView`를 보내면 화면은 **연출이 도착할 때 그 부분을 새 상태로 바꾼다**(Claude의 결정 — "진짜 게임처럼"이 목표라서). 예: 뽑은 카드는 날아와 도착하는 순간 손패에 들어가고, 하트는 피격 연출 때 꺼진다.

- **표시용 상태 층**: 화면은 "지금 보여주는 view"와 "도착한 최신 view"를 따로 갖는다. 연출 큐를 하나씩 재생하면서 각 연출이 끝날 때 해당 부분(그 자리의 체력, 손패 장수, 장비, 내 손패, 덱 장수, 버린 카드 맨 위, 역할 공개)만 최신 값으로 넘긴다. 큐가 비면 보여주는 view = 최신 view.
- **밀림 방지**: 큐에 남은 연출의 총 길이가 1.5초를 넘으면 남은 연출을 2배속으로, 3초를 넘으면 남은 연출을 건너뛰고 최신 view로 바로 맞춘다. 포격·갑판 난투처럼 한 번에 여러 명이 맞는 건 대상별 피격 연출을 동시에 재생한다.
- **조작**: 응답 창과 손패 조작은 항상 **최신 view** 기준으로 판단한다(연출 중에도 내 차례면 누를 수 있음). 연출 중에 내 손패에 아직 도착하지 않은 카드는 누를 수 없다(도착 후 활성화).
- 연출은 이벤트 순서대로 0.1~0.15초 간격을 두고 시작하며, 각 연출은 0.6초 이하.

| 이벤트 | 연출 |
|---|---|
| `draw` / `drawCards` | 덱에서 카드 뒷면이 날아가 받는 사람에게. 나라면 손패에 도착하며 앞면으로 뒤집힘 |
| `play` (즉시 사용 카드) | 내는 사람(내 손패 또는 상대 패널)에서 카드가 버린 카드 더미로 날아감. 대상이 있으면 대상 패널 쪽으로 잠깐 향했다가 더미로 |
| `play` (장비) | 카드가 장착되는 사람의 장비 자리로 날아가 놓임 |
| `respond` | 응답한 사람에서 버린 카드 더미로 |
| `damage` | 맞은 패널이 좌우로 흔들리고 빨간 "-N"이 떠오름. 하트가 하나씩 꺼짐 |
| `heal` | 초록 "+N"이 떠오르고 하트가 켜짐 |
| `judge` | 덱 옆 판정 자리에서 카드가 뒤집혀 보이고, 성공이면 초록 테두리, 실패면 빨강, 그 뒤 버린 카드로 |
| `steal` | 빼앗긴 사람에서 가져간 사람에게 카드(손패면 뒷면)가 날아감 |
| `discardCards` | 그 사람에서 버린 카드 더미로 |
| `death` | 패널이 흑백으로 바래고 역할 카드가 뒤집혀 공개 |
| `turnStart` | 그 사람 패널의 금빛 테두리가 켜짐, 내 턴이면 "내 차례!" 띠가 잠깐 |
| `characterChosen` | 뽑기 화면에서 그 자리의 상태가 "고름"으로 바뀜 |

- 손패·장비 줄의 정렬이 바뀔 때는 Framer Motion의 레이아웃 애니메이션으로 부드럽게 자리 이동.
- 이동 연출은 화면 위에 겹친 "유령 카드"로 그리며, 출발·도착 위치는 각 영역(덱, 버린 카드, 상대 패널, 내 손패, 장비 줄)의 화면상 위치로 잡는다.
- 이벤트 → 연출 목록 변환은 순수 함수(`새로 생긴 이벤트들 → 연출 목록`)로 분리해서 테스트한다.
- **이벤트 번호** (Claude의 결정): 엔진이 이벤트마다 1부터 증가하는 `seq` 번호를 붙이고, `PlayerView.events`에도 그대로 담는다. 화면은 마지막으로 본 `seq`보다 큰 이벤트만 새 이벤트로 취급한다. 같은 내용의 이벤트가 연달아 와도 구분되고, 최근 100개 창이 밀려도 안전하다. 이건 애니메이션 전용 정보가 아니라 일반적인 이벤트 식별자이므로 엔진·방장이 애니메이션을 모른다는 제약은 그대로 지켜진다.
- AI 행동 간격(현재 0.7초)은 연출 길이에 맞춰 조정 가능(구현자 판단, 0.7~1.0초).

## 7. 테스트
- 엔진: 뽑기 순서(선장부터), 후보 2장이 서로 다르고 이미 고른 캐릭터와 겹치지 않음, 7명에서도 끝까지 뽑힘, 후보 밖 캐릭터 거부, 뽑은 뒤 체력·손패, `characters` 강제 시 뽑기 생략, 기본 행동.
- 화면 상태: 남의 `chooseCharacter.options`가 가려짐, 뽑기 전 `character = null`.
- AI: 뽑기 응답, 기존 300판 시뮬레이션이 뽑기 단계 포함으로도 통과.
- 화면: 연출 변환 함수 단위 테스트(이벤트 종류별), 시작 → 역할 확인 → 캐릭터 선택 → 테이블 흐름, 기존 "관전 중/결과 화면" 테스트 유지. 테스트에서는 애니메이션을 끄는 옵션을 쓴다.

## 8. Claude가 정한 것 (수정 가능)
- 뽑기는 선장부터 순서대로, 공유 풀에서 2장씩(5.1).
- 남의 후보 캐릭터는 비공개(5.3).

- "동작 줄이기" 설정 존중.
