# 해적 숨겨진 역할 카드 게임 — 설계 문서

- 작성일: 2026-11-19
- 가제: **반란의 돛** (이름은 나중에 바꿔도 됨)
- 상태: 승인됨 (2026-11-19)

## 1. 의도와 배경

아는 친구들끼리 놀기 위한 웹 카드 게임이다. 사용자는 예전에 Java로(상속 구조를 공부하며) 비슷한 게임을 만든 적이 있는데, 코드가 사라져서 이번에는 웹으로 새로 만든다.

게임은 **숨겨진 역할 카드 게임 장르**(숨겨진 역할, 사거리, 공격과 회피, 장착 카드)의 규칙 뼈대를 따르되, **이름·캐릭터·카드·그림·테마는 전부 새로 만든 해적 테마**다. 원작의 이름, 캐릭터, 카드 이름, 그림, 문구는 어디에도 쓰지 않는다. 원작과 구분되도록 해적만의 규칙(바다 이벤트)을 하나 얹는다.

## 2. 목표 / 비목표 / 실패 조건

**목표 (1단계)**
- 한 브라우저에서 나 1명 + AI 3~6명으로 끝까지 한 판을 플레이할 수 있다.
- 기본 카드와 캐릭터 전부가 규칙대로 동작한다.
- 코드가 "규칙 엔진 / 방장 로직 / 연결 방식 / 화면" 층으로 나뉘어 있어서, 나중에 연결 방식 구현체만 추가하면 온라인 멀티플레이가 된다.

**이후 단계**
- 2단계: 바다 이벤트 카드 추가.
- 3단계: WebRTC(PeerJS)로 방장 브라우저가 서버 역할을 하는 온라인 멀티플레이. 방 코드로 입장.

**비목표**
- 회원가입, 랭킹, 매치메이킹, 전적 저장.
- 화려한 애니메이션·효과음. 깔끔하고 알아보기 쉬우면 충분하다.
- 방장의 부정행위 방지(방장 브라우저는 모든 패를 갖고 있음 — 친구끼리라 허용).
- 1단계에서 실제 네트워크 연결.

**실패 조건 (동작해도 실패로 보는 것)**
- 원작의 이름·캐릭터·카드 문구·그림을 그대로 쓰거나 살짝 바꾼 수준인 것.
- 화면이나 AI가 자기에게 허용되지 않은 정보(남의 손패, 남의 역할)를 받는 구조. 1인 플레이에서도 지켜야 3단계가 그대로 된다.
- 연결 방식을 바꿀 때 규칙 엔진이나 화면 코드를 고쳐야 하는 구조.

## 3. 제약

- 호스팅 서버를 따로 두지 않는다. 결과물은 정적 파일(GitHub Pages 등에 올릴 수 있는 형태).
- 3단계에서도 방장 브라우저가 판정을 맡는다(외부 서비스는 PeerJS 공개 중개 서버만 연결 시작 때 사용).
- 화면 언어는 한국어.
- 데스크톱 브라우저 우선. 휴대폰에서도 깨지지 않을 정도면 됨.

## 4. 검토한 방식 (Approaches)

**호스팅 (3단계용)**
1. WebRTC + PeerJS, 방장 브라우저가 서버 — **선택**. 링크와 방 코드만으로 친구들이 각자 집에서 접속 가능. 단점: 까다로운 네트워크에서 가끔 연결 실패, 공개 중개 서버 의존.
2. 방장이 Node.js 서버 프로그램 실행 — 외부 의존 없음. 단점: 원격 접속엔 포트포워딩이나 터널링 필요.
3. 같은 와이파이 전용 — 가장 단순하지만 원격 불가.

연결 방식을 인터페이스로 분리하므로 나중에 2번을 추가할 수 있다. 사용자는 "멀티플레이는 인터페이스만 만들고 1인 플레이부터"로 결정했다.

**테마**: 해적 / 정통 판타지 / 스팀펑크 판타지 중 사용자가 **해적** 선택. 해적이 원작과 분위기가 가장 가까워서, 원작과 구분되는 해적 규칙(바다 이벤트)을 얹기로 함.

**규칙 범위**: 원작 뼈대 그대로 / 뼈대 + 해적 규칙 1~2개 / 크게 변형 중 **뼈대 + 해적 규칙** 선택.

**화면 기술**: React + Vite / 순수 TypeScript + DOM / Phaser 게임 엔진 중 **React + Vite** 선택. 상태를 받아 그리는 방식이 방장이 보내는 "플레이어별 화면 상태" 구조와 맞고, 카드 게임에 게임 엔진은 불필요.

## 5. 구조

```
src/
  engine/   규칙 엔진. 순수 TypeScript, 화면·네트워크를 모름
  host/     방장 세션. 엔진을 돌리고, 플레이어별로 보일 정보만 골라 전송
  net/      연결 방식 인터페이스 + 구현체 (1단계: 로컬 메모리 구현만)
  ai/       AI 플레이어. 사람과 똑같이 연결을 통해 붙음
  ui/       React 화면
```

### 5.1 규칙 엔진 (`engine/`)
- 게임 상태 + "행동을 받아 새 상태와 이벤트 로그를 만드는" 함수/클래스 구조.
- 카드는 클래스 상속으로 표현한다(사용자가 예전에 상속을 공부하던 구조를 잇는다).
  예: `Card` → `ActionCard`(즉시 사용) / `EquipmentCard`(장착) → `WeaponCard` 등. 카드마다 `canPlay`, `play` 같은 메서드를 가진다. 캐릭터 능력도 공통 부모 클래스에서 확장.
- 난수는 시드를 받는 난수 생성기를 써서, 같은 시드면 같은 판이 재현되게 한다(테스트용).
- **응답 대기**: 공격을 받으면 대상이 "피하기를 낼지/맞을지"를 골라야 한다. 엔진은 "지금 누구의 어떤 응답을 기다리는지"를 상태로 갖고, 그 응답이 올 때까지 진행을 멈춘다. 여러 명이 응답해야 하는 카드(포격, 갑판 난투)는 앉은 순서대로 한 명씩 응답받는다.
- 1단계에는 시간 제한이 없다(사람 응답을 무한정 기다림).
- **시간 제한 자리 (3단계 대비, 사용자 결정)**: 모든 응답 대기 상태는 "시간 초과 시 기본 선택"을 정의해 둔다 — 공격·포격 응답 → 맞기, 갑판 난투·결투 → 칼질 안 냄, 전리품 분배 → 첫 번째 카드, 턴 → 턴 종료(넘치는 손패는 무작위로 자동 버리기). 3단계 기본값은 응답 30초, 턴 90초. 타이머는 엔진이 아니라 방장 세션이 돌리고, 시간이 다 되면 기본 선택을 일반 행동처럼 엔진에 넣는다. 1단계에서는 타이머를 끈다.

### 5.2 방장 세션 (`host/`)
- 엔진 인스턴스를 하나 가진다.
- 플레이어들로부터 "하고 싶은 행동" 메시지를 받아 엔진에 넘기고, 엔진이 거부하면 그 플레이어에게 거부 사유를 돌려준다.
- 상태가 바뀔 때마다 플레이어마다 **그 사람이 볼 수 있는 정보만 담은 화면 상태**를 만들어 보낸다.
  - 보이는 것: 자기 손패, 자기 역할, 선장의 역할, 쓰러진 플레이어의 역할, 모든 사람의 장착 카드·체력·손패 장수·캐릭터, 버린 카드 맨 위, 덱 장수, 공개 이벤트 로그.
  - 안 보이는 것: 남의 손패 내용, 살아있는 다른 사람의 역할(선장 제외), 덱 순서.

- **자리와 조종자 분리 (3단계 대비, 사용자 결정)**: 엔진은 "자리(seat)"만 알고, 방장 세션이 자리마다 지금 조종하는 쪽(사람 연결 또는 AI)을 연결해 둔다. 이 연결은 게임 도중 바뀔 수 있다.
  - 사람 연결이 끊기면 그 자리를 AI가 즉시 이어받는다. 같은 사람이 다시 들어오면(자리 식별 토큰으로 확인) 자리를 돌려받고, 방장은 전체 화면 상태를 다시 보낸다.
  - 온라인 게임에서 빈자리는 AI가 채운다(Claude의 결정).
  - 1단계에서는 사람 자리 1개 + AI 자리로 같은 구조를 쓴다.

### 5.3 연결 방식 (`net/`)
- 인터페이스: 메시지 보내기, 메시지 받기 콜백 등록, 연결 끊기. 메시지는 JSON으로 직렬화 가능한 형태여야 한다(3단계에서 그대로 네트워크로 보내기 위해).
- 1단계 구현체: 같은 페이지 안에서 메시지를 주고받는 로컬 구현. 사람 화면과 AI 모두 이걸로 방장에 붙는다.
- 3단계: WebRTC(PeerJS) 구현체를 추가. 이때 `engine/`, `host/`, `ui/`는 고치지 않는 것이 목표.

### 5.4 AI (`ai/`)
- 자기 화면 상태만 보고 행동을 고른다(남의 손패나 역할을 엿보지 않음).
- 수준: "같이 놀 만한 정도". 규칙 기반 판단이면 충분.
  - 역할별 목표에 맞게 공격 대상을 고른다(예: 반란 선원은 선장 우선, 충성 선원은 선장을 공격한 사람 우선).
  - 다른 사람의 행동(누구를 공격했는지 등)을 보고 "적일 가능성"을 추정한다.
  - 체력이 낮으면 회복 우선, 피하기는 아껴둔다 등 기본 판단.
- 사람이 따라갈 수 있도록 AI 행동 사이에 짧은 지연(약 0.5~1초)을 둔다.

### 5.5 화면 (`ui/`)
방장이 보낸 화면 상태를 그리기만 하고, 사용자 조작을 행동 메시지로 바꿔 보낸다. 규칙 판단은 하지 않는다(어떤 카드를 낼 수 있는지 표시하는 정도는 화면 상태에 담아 받는다).

```
┌──────────────────────────────────────────────┐
│        [AI 2]          [AI 3]       [AI 4]   │
│      ♥♥♥ 손패5       ♥♥♥♥ 손패3    ♥♥ 손패4  │
│      장비: 머스킷     장비: 보트              │
│                                              │
│ [AI 1]       덱 42장   버린 카드 [칼질]       │
│ 선장 👑                                       │
│                   진행 로그                   │
│              "AI 2가 AI 3에게 칼질!"          │
│                                              │
│  나: 반란 선원 · 캐릭터: 요리사 톰 · ♥♥♥♥      │
│  장비: [권총]                                 │
│  손패: [칼질] [피하기] [럼주] [소매치기] [칼질] │
│                          [턴 종료]            │
└──────────────────────────────────────────────┘
```
- 화면 흐름: 시작 화면(인원 수, 내 이름 입력) → 게임 → 결과 화면(승리 팀과 모든 역할 공개).
- 시작 화면은 "게임 설정을 만드는 부분"과 "게임을 진행하는 부분"을 나눠 둔다. 3단계의 대기실(방 만들기, 방 코드 입장)은 설정 부분을 대신하는 새 화면으로 추가한다(Claude의 결정).
- 카드를 누르면 대상 선택이 필요한 경우 대상 후보를 강조한다. 사거리 밖은 선택 불가로 표시.
- 응답이 필요할 때(공격받음 등) 화면 가운데에 선택창을 띄운다.
- 카드 그림은 1단계에서 이모지 + 색 박스로 대신한다.

## 6. 게임 규칙

원작 장르의 규칙 뼈대를 따른다. 아래 이름과 문구는 모두 이 게임 고유의 것이다.

### 6.1 역할

| 역할 | 공개 | 승리 조건 |
|---|---|---|
| 선장 | 처음부터 공개 | 반란 선원과 첩자가 모두 쓰러짐 |
| 충성 선원 | 비공개 | 선장과 같음 |
| 반란 선원 | 비공개 | 선장이 쓰러짐 |
| 첩자 | 비공개 | 마지막까지 혼자 살아남음 (선장을 마지막에 쓰러뜨림) |

인원별 구성:
- 4명: 선장, 첩자, 반란 2
- 5명: 선장, 첩자, 반란 2, 충성 1
- 6명: 선장, 첩자, 반란 3, 충성 1
- 7명: 선장, 첩자, 반란 3, 충성 2

- 선장이 쓰러졌을 때 첩자만 살아있으면 첩자 승리, 그 외에는 반란 선원 승리.
- 1인 플레이에서 사람의 역할은 무작위.

### 6.2 기본 진행
- 각자 캐릭터 1장을 무작위로 받는다(1단계는 선택 없이 무작위). 체력 = 캐릭터 체력, 선장은 +1.
- 처음 손패 = 체력만큼.
- 선장부터 시계 방향으로 턴 진행.
- 턴 순서: ① 카드 2장 뽑기 → ② 원하는 만큼 카드 사용 → ③ 손패가 현재 체력보다 많으면 초과분 버리기.
- **칼질은 한 턴에 1번만**(쌍권총 장착 시 제한 없음).
- 같은 이름의 장비는 동시에 1개만. 무기는 1개만 장착 가능(새 무기를 끼우면 기존 무기는 버림).
- 체력이 0이 되면 쓰러지려는 순간 손패의 럼주를 내서 버틸 수 있다(2명만 남았을 땐 불가). 쓰러지면 역할 공개, 손패·장비는 버림.
- 보상/벌칙: 반란 선원을 쓰러뜨린 사람은 카드 3장 뽑기. 선장이 충성 선원을 쓰러뜨리면 선장은 손패와 장비를 전부 버림.
- 덱이 떨어지면 버린 카드 더미를 섞어 새 덱으로.

### 6.3 거리
- 앉은 자리 기준으로 양쪽 중 가까운 쪽의 칸 수 (바로 옆 = 1). 쓰러진 사람은 자리에서 빠진다.
- 내가 상대를 볼 때: 기본 거리 − 내 망원경(−1) + 상대 보트(+1). 최소 1.
- 칼질은 "상대까지 거리 ≤ 내 무기 사거리"일 때만 가능. 무기가 없으면 사거리 1(맨손/단검).
- 소매치기는 거리 1인 상대에게만.

### 6.4 판정
일부 카드는 덱 맨 위 1장을 뒤집어 문양으로 판정한다. 그래서 모든 카드에 문양(♠♥♦♣)과 숫자(2~A)가 있다. 문양·숫자 배정은 구현자가 정하되, 다음 조건을 지킨다 (Claude의 결정):
- 80장을 문양마다 20장씩 고르게 나눈다 → ♥ 판정 성공률 약 25%.
- ♠ 20장 중 숫자 2~9가 12장 정도 → 화약통 폭발 확률 약 15%.
- 한 종류의 카드가 한 문양에 몰리지 않게 섞는다.

### 6.7 바다 이벤트 (2단계)
- 이벤트 카드 덱(약 10~12장)을 따로 둔다. 매 라운드 선장 턴 시작 시 1장을 공개하고, 다음 공개 전까지 모두에게 적용.
- 예: 폭풍(모든 거리 +1), 순풍(뽑기 3장), 바다 안개(망원경·보트 무효), 해적 깃발 축제(이번 라운드 칼질 2회 가능), 바다 괴물(공개 즉시 전원 판정, ♠이면 체력 1 잃음), 고요한 바다(아무 효과 없음).
- 엔진은 1단계부터 "현재 적용 중인 규칙 변경"을 끼울 자리를 갖고 있어야 한다(거리 계산, 뽑기 장수, 칼질 횟수 제한 등을 하드코딩하지 말고 계산 함수를 거치게).
- 목록과 균형은 2단계에서 확정.

## 7. 테스트
- 규칙 엔진은 Vitest로 테스트한다. 카드 효과, 거리 계산, 승리 조건, 응답 대기 흐름, 쓰러짐과 보상/벌칙.
- 시드 고정 난수로 판 전체를 재현하는 테스트를 둔다.
- AI끼리만 수백 판을 돌려서 예외 없이 끝나는지 확인하는 테스트(게임이 멈추거나 끝나지 않는 경우 탐지).
- 방장 세션이 플레이어별 화면 상태에서 남의 손패·역할을 빼는지 테스트.

## 8. 기술 결정 (Claude가 정한 것, 수정 가능)
- TypeScript + React + Vite, 테스트는 Vitest.
- 상태 관리 라이브러리는 쓰지 않는다(화면은 방장이 보낸 화면 상태 하나만 그리면 됨).
- 프로젝트 루트: 저장소 루트.
- 문서상의 가제, 카드 장수, 캐릭터 목록, 바다 이벤트 예시는 Claude의 초안.

## 9. 구현자에게 맡기는 것
- 파일 세부 구조, 클래스 이름, 메시지 형식의 구체적인 필드.
- 카드별 문양·숫자 배정 (판정 확률 조건만 지키면 됨).
- AI 판단 규칙의 세부 사항과 가중치.
- 화면 스타일링, 색, 배치의 세부 사항(위 스케치의 정보만 담기면 됨).
